# v6.4 (experimental) — UI de estado honesto, diagnóstico e observabilidade BGFT

## Base preservada

O APK de referência **v6.3.1**, assinado com certificado SHA-256
`3d8daee7afa38dedd1378f6a6dd0c7cf6604785ef594413c344a5f94e1d56219`,
foi validado no PS4 físico pelo proprietário em 19/10/2026: descoberta UDP,
validação do PKG Just Cause 4 (`CUSA09254`), envio de ELF via GoldHEN
BinLoader TCP 9090, download BGFT, instalação e jogo funcionando.

**Não modificar** produção Worker `seek`, `BgftRoutePlanner.cs`,
`Integration.cs`, `DownloadCore.cs`, `ManualSendGuard.cs` e ELF
sem necessidade demonstrada. Esses cinco arquivos foram comparados entre
a base v6.3.1 e a branch v6.4: **conteúdo idêntico**.

## 1. Corrigir falso estado “ELF pronto”

- Introduzido `UiStageTracker` com fases por link: aguardando, recebido,
  validando, validado, ELF gerado, enviando, ELF transmitido, falha.
- **Nunca usar `btnInjetar.IsEnabled` como evidência de ELF pronto**.
- Trocar ou apagar o URL invalida os estados da operação anterior, inclusive
  respostas assíncronas atrasadas.
- O pipeline atualiza a etapa apenas após validar o PKG, gerar o ELF
  com sucesso e concluir a escrita TCP, respectivamente.
- A indicação de ELF transmitido **não** declara conclusão BGFT.
- Se o usuário alterar o URL após gerar o ELF e antes de o envio iniciar,
  o fluxo automático cancela a operação sem contatar a porta 9090.

## 2. Diagnóstico seguro e útil

- Erros categorizados por contexto: recusa TCP 9090, tempo esgotado,
  PS4 inacessível, conexão perdida em envio parcial, HTTP Worker, formato
  inválido e erro inesperado.
- Mensagens **não incluem exceção.Message** nem links assinados.
- Ao perder conexão depois de iniciar a transmissão, o aplicativo
  **não reenvia automaticamente** (risco de duplicar o registro BGFT).

## 3. Acompanhamento BGFT honesto

- Histórico apresenta botão opcional **“Marcar download visto no PS4 (manual)”**
  somente se o envio TCP tiver sido registrado.
- Estado `BAIXANDO (MANUAL)` conserva a origem da informação; o usuário
  pode confirmar conclusão/instalação na etapa existente.
- **Progresso percentual automático: NÃO implementado.**
  O endpoint GoldHEN BinLoader TCP 9090 usado no fluxo atual aceita bytes
  do payload, mas **não disponibiliza task_id nem API de progresso BGFT**.
  Exibir porcentagem inventada ou usar conexão TCP como prova de BGFT
  seria tecnicamente incorreto.
- Para telemetria automática futura seria necessário definir uma
  interface de leitura na ponta PS4 (serviço/status por tarefa, com
  task ID e formato documentado) e **validá-la sem alterar a arquitetura
  funcional**. Não adicionamos aplicativos paralelos ou servidores LAN.
