# Recuperação de assinatura da v6.1 — Tayson PS4 Payload Generator

## Situação verificada
A versão experimental v6.1 instalada foi assinada com certificado SHA-256:

`c693d66ac7e2c95411c730aefa0c9da62a617586e9b3a5d57d0dd90ab8f62ec5`

O único keystore de assinatura APK identificado no ambiente de compilação atual tem certificado diferente:

`12982c4b170f6d983e1a4dea6fc32c7464f70239bdace4562888152f66ef31ca`

Não é possível gerar uma assinatura compatível a partir de um APK ou de um certificado público. **A chave privada original é indispensável**. Nunca inserir chaves ou senhas em mensagens, repositórios públicos ou logs.

## Fontes verificadas
- Arquivos de assinatura do ambiente atual: não existe cópia local do keystore com certificado v6.1.
- Arquivos independentes JKS/keystore/P12/PFX na biblioteca: nenhum correspondente.
- Pacotes arquivados de origem/código da 3.4.3 e staging-auth (quatro ZIPs): não há keystore de assinatura.
- URL temporária que disponibilizava o APK v6.1: atualmente responde 404; mesmo um APK v6.1 íntegro não contém a chave privada.
- Não foi constatado nenhum acesso autorizado a um cofre de segredos ou ambiente anterior contendo o keystore original.

## Proteções existentes na branch
- `tools/ps4-transport-v62/verify_signing_identity.py` rejeita automaticamente certificados incompatíveis, versões Android inferiores e identificadores de pacote diferentes.
- `payload-generator/3.2.0/UPDATE/scripts/apply_release_identity.py` aceita `--storepass-ref env:NOME` e `--keypass-ref env:NOME`, para evitar escrever senhas em argumentos da linha de comando, quando uma chave original for disponibilizada por um meio seguro.
- O programa de assinatura falha se a variável de ambiente referenciada não estiver definida.
- Teste realizado com o certificado disponível confirma que ele é **rejeitado** para atualização da v6.1.

## Como retomar sem apagar dados
1. Recuperar o **arquivo original do keystore (JKS/PKCS12)** e os dados de acesso **do mesmo ambiente que assinou a v6.1**. Não confundir com APK, certificado de assinatura ou chave de API do Worker.
2. Não enviar arquivo de keystore nem senha ao chat ou ao GitHub como arquivo comum. O processo de custódia deve ser estabelecido em armazenamento restrito apropriado.
3. Antes de qualquer assinatura, conferir o fingerprint do keystore contra o certificado acima, sem divulgar o conteúdo sensível.
4. Reconstruir e assinar a v6.2 com esse keystore, manter o identificador `com.tayson.ps4payloadgenerator.staging`, aumentar o `versionCode` e validar `apksigner verify --print-certs` junto de `aapt dump badging`.
5. Distribuir o APK **somente se** certificado, package ID, assinatura e versionCode forem compatíveis. Atualizar diretamente, sem desinstalar.

Se a chave privada original tiver sido definitivamente perdida, a atualização no mesmo package ID **sem reinstalação não é possível**. Alternativas exigem consentimento explícito para reinstalar/limpar dados ou manter a v6.1 atual. Não criar aplicativo paralelo como suposta solução.

O módulo de backup não faz parte da v6.2. Os Workers Cloudflare permanecem intactos.
